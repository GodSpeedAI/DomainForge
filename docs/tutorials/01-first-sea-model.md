# Tutorial: Authoring Your First SEA Model

In this tutorial, you will create, parse, and validate a complete Semantic Enterprise Architecture (SEA) domain model from scratch using the DomainForge CLI.

---

## Prerequisites
- DomainForge CLI installed and available in your `PATH` (run `domainforge --version` to verify).
- A text editor.

---

## 1. Create a Workspace

Create a directory for your project:
```bash
mkdir my-first-model
cd my-first-model
```

---

## 2. Author the Domain Model

Create a file named `logistics.sea` and add the following content:

```sea
@namespace "logistics"
@version "1.0.0"

// 1. Declare fundamental domain entities (WHO acts)
Entity "Warehouse" in logistics
Entity "FulfillmentCenter" in logistics

// 2. Declare the resources that move (WHAT moves)
Resource "Package" units in logistics

// 3. Declare movement between entities (HOW it moves)
Flow "Package" from "Warehouse" to "FulfillmentCenter" quantity 150

// 4. Declare a business policy rule (WHAT constraints apply)
policy daily_dispatch_limit per Constraint Obligation priority 1
  @rationale "A single flow must not exceed 200 packages per dispatch"
  as:
    forall f in flows: f.quantity <= 200
```

---

## 3. Validate the Model

Run the DomainForge validator:
```bash
domainforge validate logistics.sea
```

### Expected Output
```text
Validating logistics.sea...
Model is valid! Evaluated 1 policies with 0 violations.
```
The exit code will be `0`.

---

## 4. Test Policy Violation Detection

To understand how DomainForge protects your system against rule violations, let's intentionally break the policy. Edit `logistics.sea` and change the flow quantity from `150` to `250`:

```sea
Flow "Package" from "Warehouse" to "FulfillmentCenter" quantity 250
```

Run validation again:
```bash
domainforge validate logistics.sea
```

### Expected Output
```text
Validating logistics.sea...
Error [policy:daily_dispatch_limit]: Policy evaluation failed: A single flow must not exceed 200 packages per dispatch
Validation failed with 1 error(s).
```
The exit code is `1`. Revert the quantity back to `150` so your model is valid again.

---

## 5. Inspect the Parsed AST and Graph

You can view the internal structure generated by DomainForge:

### View Abstract Syntax Tree (AST):
```bash
domainforge parse logistics.sea --ast --format json
```

### View Relational Graph JSON:
```bash
domainforge parse logistics.sea --format json
```
Notice that the entities, resources, and flows have been assigned deterministic `ConceptId` identifiers computed via UUID v5.
